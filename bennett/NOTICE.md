# Bennett Legal modifications to DocuSeal

This image is built from the public fork <https://github.com/TheHomelessCoder/docuseal>, branch `bennett-legal`. The exact source commit is the image label `org.opencontainers.image.revision`. That fork is the complete corresponding source: DocuSeal's own `Dockerfile` builds the application from it unmodified, and `bennett/Dockerfile.bennett` adds this runtime layer.

DocuSeal is copyright DocuSeal LLC and licensed under the GNU Affero General Public License v3.0 (`/app/LICENSE`), with the additional terms in `/app/LICENSE_ADDITIONAL_TERMS`. Both files are unchanged. The original DocuSeal attribution stays visible: a "Powered by DocuSeal" link in the signer masthead, the attribution below each document, and the email attribution footer. No licence or paid-feature check is changed.

## What Bennett Legal changed

Each change is a normal commit on `bennett-legal`; `git log upstream/master..bennett-legal` lists them.

- **Recipient order before signer mutations** (2026-11-01). Form value and completion updates, uploads, prefill attachments, decline and invitation call the existing `Submitters::AuthorizedForForm` with `with_order: true`. A later signer cannot change a submission before the earlier signers finish. Upload and prefill routes also refuse view-only recipients. OTP and link authentication, lifecycle guards and prefill-token checks are unchanged. Each modified controller carries a dated notice.
- **Signer chrome and emails** (2026-11-02/03). The Bennett Legal masthead, colours and fonts; a details card, page counter and "go to where you sign" control (`public/packs/bennett-signing-v1.js`, same-origin, writes text only); the signer's stored language before the browser's; Bennett Legal invitation, verification-code and signed-copy emails in English and Spanish. Since 2026-11-04 every email uses the firm's intake nurture letterhead (`app/views/layouts/mailer.html.erb`), with dark-mode rules and DocuSeal's email attribution in its footer (`app/views/shared/_mailer_attribution.html.erb`, same text and conditions as upstream's). Signing, authorization, OTP, field and PDF logic are unchanged. The Jost and Noto Serif fonts are under the SIL Open Font License; the licence texts are in `public/fonts/`.
- **Runtime layer** (`bennett/`). `launch.rb` checks the source invariants in `source_check.rb` and the database, queue and key configuration before any service starts. `puma.rb` keeps upstream's Puma configuration and changes only the bind address. `storage.yml` stores uploaded objects with `private, no-store` cache metadata. `rds-global-bundle.pem` is the public AWS RDS trust bundle (`ca-provenance.json`).
- **Inline email artwork** (2026-11-05). `ApplicationMailer` attaches the firm's existing nurture logo and social icons as inline PNG MIME parts. The letterhead references their Content-IDs, removing its dependency on remote image downloads. The artwork, copy, links and DocuSeal attribution are unchanged.
- **Dependency security patches** (2026-11-05). The application lockfile selects Rails 8.1.4.1 and Rack 3.2.8, with the HTML sanitizer, Loofah and Nokogiri patch versions required by Rails. This addresses the image scan's Rails/Active Storage and Rack findings; the scan gate and its existing, separately documented default-JSON exception are unchanged.
- **Staff Access and workspace** (2026-11-08). An opt-in staff host verifies Cloudflare Access application assertions and maps the signed email to an existing, active DocuSeal user. It does not provision users, change permissions, accept integration tokens, or bypass configured native authenticator verification. The staff workspace uses JUD's slate and amber palette, Jost type, responsive navigation, and light/dark/system appearance. Both native layouts retain visible DocuSeal attribution and its logo. Public signer authentication, branding and document behavior are unchanged.
- **Staff workspace design** (2026-11-09). The staff shell follows JUD's Inter/system type, slate and charcoal surfaces, amber actions, compact navigation and page headings. Templates and submissions use flat rows; settings, document viewing, the editor, dialogs and event history share the theme and control scale. The editor uses staff surface tokens instead of a fixed light background. Staff dialogs contain keyboard focus and return it on close. Shared controls receive accessible names and table headings. Signing, document contents, native permissions, paid-feature checks and staff authentication are unchanged. The original DocuSeal logos, attribution and source link remain visible.
- **Compact staff editor toolbar** (2026-11-09). The staff editor shows a compact document context that follows name edits and constrains the editable title on phones, keeping native editor actions accessible. Stored names and document data are unchanged.
- **Submission review controls** (2026-11-09). Staff submission lists keep search and filters available for small and empty results, including completed and archived requests. Search/filter changes reset pagination while preserving the other criteria. The submissions dashboard omits template creation and upload prompts; template management remains under Templates.
- **Mobile settings navigation** (2026-11-09). Staff settings use a compact disclosure on phones while retaining the native permission-aware navigation and controls.
- **Compact review rows and document language** (2026-11-09). Staff template/submission lists, settings tables and event timelines use tighter spacing and quieter actions. Spanish retainer badges use frozen submission document metadata before template metadata, with an exact-title fallback for legacy Bennett imports. List projections include the existing schema fields needed for those badges. Practice titles retain an explicit practice marker while shortening the displayed heading. Stored records, PDFs, signing actions, authorization and attribution are unchanged.
- **Literal recipient email search** (2026-11-10). Submission searches containing an at-sign use case-insensitive literal matching for full and partial email addresses, including aliases and wildcard characters. The authorized record scope and existing filters apply before pagination. Other queries retain the configured full-text search behavior.
- **Signature preview contrast** (2026-11-10). The staff submission details show signature and initials previews on a white paper surface in both themes, keeping the original ink readable. This changes only the review panel presentation; stored signature images, signed PDFs and audit evidence retain their original bytes.

- **JUD context in staff mail** (2026-11-10). Invitations, completion, decline and signed-copy emails can show a server-provided JUD case/lead reference. The context must match the JUD issuance and firm signer, point to the fixed JUD origin and address only the firm signer or active native staff. Invitations preserve an existing JUD link instead of duplicating it. JUD-tagged signed copies are rendered separately for each recipient; client and mixed-recipient messages do not receive the internal context. Existing signing, consent, document, account, delivery and authorization settings remain authoritative. The native email letterhead, artwork, attachments and DocuSeal attribution are preserved.

- **Staff email administration links** (2026-11-10). Completion/decline links and the `{submission.link}` email variable use the validated Access staff host when selected. Public signer and signed-document links retain their existing destination. An invalid staff configuration omits that administration link without suppressing document-copy mail.

- **Per-agreement document header** (2026-11-10). New JUD-tagged agreement previews and generated results can show the native DocuSeal document ID in the upper-left margin on every page. It reuses the submission's existing reference, respects the account signature-ID setting and avoids duplicate headers across generation passes. Native footer/audit references and existing stored signed documents remain intact. Ordinary uploads without validated JUD context retain their prior behavior.
